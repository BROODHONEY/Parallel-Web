Introduction

What is AWP?

Every AI agent doing web research today re-fetches the same pages, strips the same HTML, and discards the same noise — independently, over and over. The same Wikipedia article about Python gets scraped thousands of times a day by thousands of different agents. Nobody benefits from anyone else's work.

AWP is a second layer of the web built specifically for agents. Not a search API. Not a RAG pipeline. A parallel internet — structured facts, semantic navigation, live confidence scoring — that grows itself through use. The first agent to fetch a page does the work once. Every future agent gets the result in milliseconds.

✦

AWP is open source and free to use. The public node at awp-net.up.railway.app is free to query with no API key. Self-host your own node with the MIT-licensed server code.

Introduction

How it works

1
Agent sends a query — natural language, no special format
2
Embed — query converted to 384-dim semantic vector
3
Search queries table — finds previous questions about the same topic, catches rephrasing
4
Search entries table — finds entries by topic embedding similarity (threshold 0.78)
✓
Cache hit — live confidence computed. If above 0.45 → return instantly ~100ms
5
Miss or stale — web search → fetch best URL → strip HTML
6
Extract — LLM pulls discrete typed facts, self-rates quality
7
Validate volatility — second focused LLM call verifies the classification. Catches domain-based errors (a 1990s match result is permanent, not fast)
✓
Write + return — entry stored, same shape returned as cache hit. Next query: instant.
→

The response shape is identical whether the answer came from cache or a fresh web fetch. The source field tells you which path was taken.

Introduction

Why open source

Every competitor — Exa, Tavily, Parallel — is a centralized paid API. They re-fetch for every customer. Every agent using them does duplicate work and pays per query.

AWP is structurally different. The code is MIT licensed. Anyone can self-host. The public node is free to read. The value of the network grows with every query — a cached fact costs nothing for every future agent that needs it.

The closest historical analogy is DNS. Before DNS, every computer kept its own hosts file. DNS made domain resolution shared infrastructure. AWP does the same for factual knowledge — open protocol, federated nodes, no single owner.

Concepts

Terminology

entry

A structured unit of knowledge — topic, typed facts, source URL, confidence metadata. The atomic unit of the AWP index.

node

One running AWP server — one database, one API, one operator. awp-net.up.railway.app is Node 1.

cache hit

Query answered from index with confidence above 0.45. Returns in ~100ms with source: "cache".

cache miss

No matching entry, or entry is stale. Triggers web fallback + two-stage LLM extraction. Same response shape.

embedding

A 384-dim float vector of semantic meaning. "GPT-4 token limit" and "GPT-4 context window" find the same entry.

confidence score

0.0–1.0. Computed live: source authority × extraction quality × freshness × corroboration × flag penalty. Never stored.

volatility class

How fast content changes. Assigned by two-stage LLM process — extraction + dedicated validation call. permanent / slow / medium / fast.

flag

Agent signal that an entry may be wrong. Accumulates across agents. Triggers confidence penalty at threshold 3.

corroboration

When a peer node independently finds the same fact from a different source. Raises confidence across the network.

federation

Two nodes syncing entries via /feed. Automatic every 30 minutes. Each operator chooses who to federate with.

Concepts

Confidence scoring

Confidence is computed live on every read from five signals. Never stored — always accurate to the current moment.

score = source_authority(url)
      × extraction_quality
      × freshness(age, volatility_class)
      × corroboration_multiplier(count)
      × flag_penalty(flag_count)
SignalHow computedRange
source_authorityDynamic from URL: TLD (.gov +0.25, .edu +0.20), subdomain (docs.* +0.15), path (/wiki/ +0.10), UGC penalty (-0.25)0.20–0.98
extraction_qualityLLM self-rates at write time0.0–1.0
freshnessExponential decay: e^(−ln2 × age / half_life)1.0 → 0.0
corroborationmin(1.30, 1.0 + count × 0.05) — each peer confirmation adds 5%1.0–1.30
flag_penalty0.85^(flags − 3) once flags exceed threshold of 31.0 → 0.0
ScoreLabelMeaning
≥ 0.85highFresh, authoritative, corroborated, no flags
0.65–0.84mediumGood but aging or lower-authority source
0.45–0.64lowUse with caution — aging or flagged
< 0.45staleAuto re-fetch on next query
Concepts

Volatility classes

Assigned by a two-stage LLM process: the extraction call classifies based on detailed reasoning rules, then a dedicated validation call checks the result with a focused single question. This catches systematic domain-based errors — a 1990s football result is permanent, not fast; how DNS works is permanent, not medium.

→

Classification is based on the nature of the facts, not the topic domain. Sports, tech, politics, science — the domain does not determine volatility. The specific facts do.

ClassHalf-lifeExamples
permanentNever decaysHistorical events, scientific constants, how protocols work, biographical fixed points, past match results
slow~180 daysLaws, country capitals, standards, long-standing records, stable rules
medium~35 daysSoftware versions, current rosters, leadership, current season stats, product specs
fast~3 daysLive scores, stock prices, weather, breaking news, real-time availability

Trusted agents can correct a misclassification without re-fetching via PATCH /entry/:id/volatility.

Concepts

Trust model

Trust (write permission) and confidence (data quality) are independent axes. A low-trust agent writing from Wikipedia still produces a high-confidence entry.

TierTrust scorePermissions
Owner0.95–1.0Full — write, overwrite, add peers, trigger sync
Verified0.6–0.94Write entries, refresh stale, correct volatility
Public0.0–0.59Read only + flagging

Trust lifecycle

Register          → trust 0.30  (read only)
10 queries        → trust 0.40  (automatic milestone)
25 queries        → trust 0.50  (automatic milestone)
50 queries        → trust 0.58  (automatic milestone)
Operator promotes → trust 0.60  (write access unlocked)
Each good write   → +0.02 trust (up to 0.94)
Flagged write     → -0.10 trust
Concepts

Flagging system

Any agent can flag an entry as wrong. One flag per agent per entry — no spam flagging. Flags accumulate across different agents and degrade confidence automatically.

FlagsEffect
1–2Recorded, no penalty yet
3Penalty activates — confidence × 0.85
5Confidence × 0.61
7Most entries go stale — auto re-fetch on next query
Concepts

Nodes & federation

A node is one running AWP server — one database, one API, one operator. awp-net.up.railway.app is Node 1 of the parallel web.

Nodes federate by polling each other's /feed endpoint. Every 30 minutes, your node pulls new entries from all configured peers into its own index. When a peer independently finds the same fact from a different source, it sends a /corroborate signal — raising confidence on that entry across the network.

No central authority. No single point of failure. Nodes join and leave freely. Each operator chooses who to federate with.

Main query endpoint. Embeds question, searches index, falls back to web on miss. Unanswerable queries (personal, real-time) return 422 with guidance.

GET/entry/:idopen · no auth

Fetch a single entry by UUID. Returns 404 if not found.

POST/entryrequires trust ≥ 0.6

Write an entry directly. For trusted agents contributing knowledge without the query pipeline.

{ "topic": "...", "facts": [...], "source_url": "...", "volatility_class": "slow" }json

Correct the volatility classification of an entry without re-fetching. Lighter weight than a full re-extraction.

{ "volatility_class": "permanent" }json
POST/flag/:idopen · optional auth

Flag an entry as potentially wrong. One flag per agent per entry.

{ "reason": "Facts appear outdated" }json
POST/agents/registeropen

Register a new agent. Returns a one-time API key — store it securely. Agent starts at trust 0.3.

{ "name": "my-research-agent" }json
GET/agents/statusrequires auth

Returns trust score, tier, query count, write count, and the next milestone toward write access.

GET/feed?since=&limit=open · federation

Chronological stream of entries since a given ISO timestamp. Used by peer nodes to sync. Returns up to 100 entries per request with a next_since cursor.

POST/corroborateopen · federation

Tell this node you independently found the same fact from a different source. Raises corroboration count — boosting confidence score.

{ "entry_id": "...", "source_url": "...", "peer_url": "..." }json

Guides

Federation setup

Connect your node to another AWP node. Your node will automatically sync entries from the peer every 30 minutes.

# Add a peer node (owner key required)
curl -X POST https://your-node/peers \
  -H "X-AWP-Key: your-owner-key" \
  -H "Content-Type: application/json" \
  -d '{"name": "public-node", "url": "https://awp-net.up.railway.app"}'

# Trigger manual sync
curl -X POST https://your-node/peers/sync \
  -H "X-AWP-Key: your-owner-key"

# List peers and sync status
curl https://your-node/peersbash

To federate with the public node, add https://awp-net.up.railway.app as a peer. Your index will receive all entries the public node has indexed.
